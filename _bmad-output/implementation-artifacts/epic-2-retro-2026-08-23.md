## 4. What Went Well (Strengths & Architectural Successes)

- **Zero Raw-Message Leakage & Privacy Boundary (AD-3, AD-8):** Structurally excluded content and irrelevant chatter are immediately dropped. Raw message payloads never appear in routine logs, audit dumps, or permanent storage.
- **Deterministic Time Bucketing (AD-2):** Computing `Asia/Tashkent` UTC+5 calendar days strictly at ingress guarantees replay and worker retries produce identical ordering and clustering.
- **CAS Concurrency Control (AD-4):** Dual-layer optimistic locking on `topics` (`revision`) and `topics_projection` (`generation`) eliminated race conditions during concurrent burst signal processing.
- **1:N Authoritative AI Lineage (AD-7):** Pinned prompt profiles (`prof_rel_2026_08_v1`, `prof_sum_2026_08_v1`), 12 standardized error codes, token usage tracking, and P95 latency aggregation provide complete operational transparency.
- **Contract-First Rigor:** `@mahalla-ovozi/api-contracts` with Zod validation kept schemas perfectly aligned across Fastify routes, worker queues, and test assertions.

## 5. Technical Friction Points & Lessons Learned

1. **PostgreSQL Connection Pool Management in Concurrent Tests:**
   - *Friction:* Vitest integration tests executing multiple workers concurrently could saturate the connection pool if `Promise.all` loops spawned unconstrained connections.
   - *Resolution:* Scoped transaction blocks, sequential teardown hooks, and explicit connection releases were standardized across all test suites.
2. **CAS Generation Conflict Handling in Burst Ingress:**
   - *Friction:* Rapid synthetic message bursts targeting the same Mahalla caused projection generation conflicts.
   - *Resolution:* Implemented retry backoffs with fresh database re-reads in the topic assignment service.
3. **Multi-District Tenant Guardrails:**
   - *Friction:* Need to ensure background workers never inadvertently cross district boundaries when queuing downstream jobs.
   - *Resolution:* Enforced strict, non-nullable `districtId` in all job payload schemas and verified isolation via dedicated multi-tenant integration tests.
