- (event) Started BMAD Architecture in Coaching path with a lean Architecture Spine as the only architecture deliverable for this run.
- (event) Inspected the latest approved PRD and PRD memlog, hardened Forge artifact and Forge memlog, final UX DESIGN/EXPERIENCE and UX memlog, technical feasibility research, repository AGENTS.md, BMAD architecture workflow/configuration, recent repository state, and architecture spine template.
- (decision) Treat approved PRD, hardened Forge, and final UX artifacts as ground truth. Treat technical research as research input only, not pre-approved architecture.
- (decision) Preserve the locked one-day AI/Topic semantics: Topic identity is District + Mahalla + Uzbekistan calendar day + same underlying situation; matching never crosses midnight; contextual AI uses complete required raw Accepted Evidence from all same-day Topics in the same Mahalla; RAG/vector retrieval/summaries/recent-window/cross-day memory cannot replace this context; context overflow is explicit failure rather than truncation.
- (decision) Preserve future-only AI configuration semantics and avoid automatic replay of completed old message-level relevance/category/topic-assignment decisions when new evidence triggers Topic-derived recalculation.
- (decision) Architecture refinement scope includes deterministic context assembly, compact lossless evidence serialization, stable ordering, idempotent/retry-safe AI, concurrency/stale-snapshot protection, efficient Topic-derived recalculation, AI configuration/profile version traceability, structured-output validation/failure handling, optional correctness-neutral prompt caching, and privacy-safe observability.
- (decision) Do not introduce embeddings, vector databases, HNSW, reranking, full-history RAG, or historical semantic retrieval in MVP unless a later concrete requirement cannot be met otherwise.
- (decision) AD-1 approved by user: use a hexagonal modular monolith. Keep one cohesive application/codebase and MVP deployment boundary; use domain-oriented modules; place project-owned ports at meaningful external/stateful boundaries; keep provider SDKs and infrastructure behind adapters; allow HTTP/webhook and worker runtime processes from the same codebase without turning them into microservices.
- (rationale) AD-1 minimizes operational and distributed-systems complexity at MVP scale while protecting provider neutrality, domain-rule consistency, testability, and agent-driven implementation from infrastructure coupling.
- (rejected) Traditional loose layering without enforced adapter boundaries: simpler initially but more likely to let AI/Telegram/database concerns leak into domain logic and drift across independently generated modules.
- (rejected) Event-driven microservices: adds network contracts, distributed failure modes, deployment/observability burden, and transaction complexity without an approved MVP scaling or organizational need.
